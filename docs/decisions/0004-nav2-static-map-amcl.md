# ADR 0004：接入 Nav2（静态地图 + AMCL + DWB）

- 状态：已接受（v2.0 步骤 11），后被 ADR 0005 部分取代
- 日期：2026-10-23

## 背景

自研避障节点是反应式局部避障，没有全局目标导航能力。
Nav2 是 ROS 2 官方导航栈，但依赖重、概念多（生命周期节点、代价地图、
行为树、恢复行为），需要评估接入成本。

## 决策

接入 Nav2 标准配置：静态地图（map_server）+ AMCL 定位 + Navfn 全局规划
+ DWB 局部控制。关键适配：

- 坐标系用 `base_link`（本项目没有 `base_footprint`）。
- footprint 取 0.32×0.26（车体 0.30×0.20 加 1cm 余量，含轮子与脚轮外缘）。
- 限速 0.2m/s / 0.8rad/s，与差速底盘能力对齐。
- AMCL 启动时直接给定初始位姿（`initial_pose.x: -2.0` 扁平键写法），
  与 spawn 位姿一致，免去 RViz 手动点 2D Pose Estimate。
- Nav2 延迟 5s 启动，等 Gazebo spawn、/scan、TF 就绪。
- AMCL `max_beams: 120`（3° 间隔），比默认 60 束更容易锁定 0.5m 小障碍。

## 理由

- Nav2 是行业标准，学会它对 ROS 2 学习的长期价值最大。
- 静态地图 + AMCL 是最小可用组合，先跑通再谈升级（后续 SLAM，见 ADR 0005）。

## 验证结果（detour_test.world）

- 生命周期节点全部 active；(-2,0) 导航到 (2,0) 再返回，绕过中心方块，
  实测最小车体间隙 0.186m，无碰撞。

## 已知限制

- world 改动后必须重画静态地图，迭代成本高 → 由 ADR 0005 解决。
- 差速底盘静止漂移约 5.5mm/s，AMCL 会持续修正，但静止越久初始位姿误差越大。

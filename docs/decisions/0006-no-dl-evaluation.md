# ADR 0006：不引入语义分割 / 目标检测（v2.0 步骤 13 评估结论）

- 状态：已接受（v2.0 步骤 13）
- 日期：2026-10-23

## 背景

v2.0 收尾前评估是否引入深度学习感知（语义分割 / 目标检测）。

## 评估依据

现有方案已覆盖：视觉可通行区域 + 雷达几何兜底 + Nav2/SLAM 全局导航，
三场景 A/B 与绕行验证均零碰撞。逐条分析真实短板：

| 短板 | DL 能否解决 |
|---|---|
| 视觉基线对光照/地面配色敏感 | 语义分割理论上更鲁棒，但 Gazebo classic 纹理简单，sim 内训练/评估域差距大，结论难迁移真实场景 |
| 无法区分障碍类别（人 vs 箱子策略应不同） | 目标检测可补，属"增强"非"必需" |
| 雷达在 0.15m 高度，看不到悬空障碍（桌沿、横杆） | **补不了**——需要深度相机或 3D 雷达，不是 2D 语义问题 |

硬件与依赖成本（2026-10-23 实测本机）：无独立 GPU（Intel UHD 核显），
torch / onnxruntime / tensorflow 均未安装；YOLOv8n 级模型 CPU 推理约
100~200ms/帧，会把感知从 15Hz 拖到 5~10Hz（当前单帧处理仅 0.3ms），
并引入 ~800MB 级依赖。

## 决策

1. 语义分割——不引入。
2. 目标检测——仅作为 v3.0 可选增强层（叠加在现有融合基线之上，不替换）。
3. 感知升级的优先方向改为**深度相机**（补悬空障碍 + 真实深度）。

## 理由

- 收益/成本不匹配：最大短板（悬空障碍）DL 无解，次短板在 sim 内无法有效验证。
- 违背 v1.0 确立的"可解释、易调试、依赖最小"基线（ADR 0001），
  且无硬件支撑。

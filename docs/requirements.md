# 项目需求与环境（M0）

## 1. 目标与范围（v1.0）

在 Gazebo 仿真中让差速移动机器人借助单目 RGB 摄像头完成：

- 持续接收图像并检测输入有效性
- 基于图像下部 ROI 生成可通行区域候选掩膜
- 对左 / 中 / 右候选方向做风险评分
- 根据评分输出前进 / 转向 / 停车指令
- 图像超时、无安全方向、编码错误时强制停车

**不做**：精确测距、深度摄像头、激光雷达、深度学习模型。

## 2. 开发环境（已验证）

| 项 | 值 |
|---|---|
| 操作系统 | Ubuntu 22.04.5 LTS |
| ROS 发行版 | ROS 2 Humble |
| 仿真器 | Gazebo classic 11.10.2 |
| 构建工具 | colcon |
| 图像处理 | OpenCV 4.5.4 + NumPy 1.21.5 |

| 已确认可用包 | xacro, robot_state_publisher, gazebo_ros, gazebo_ros_pkgs, joint_state_publisher |

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```

## 3. 接口定义（v1.0）

| 话题 | 方向 | 类型 | 说明 |
|---|---|---|---|
| /camera/image_raw | Gazebo 摄像头 → 感知节点 | sensor_msgs/Image | RGB 图像 |
| /cmd_vel | 控制 → 底盘插件 | geometry_msgs/Twist | 线速度 / 角速度 |

v1.0 只使用标准 ROS2 消息，不自定义 msg/srv。

## 4. 处理主链路

```text
Gazebo 仿真场景
  → 摄像头插件发布 /camera/image_raw
  → 感知节点：有效性检查 → ROI 分割 → 可通行掩膜 → 三分评分
  → 决策：前进 / 左转 / 右转 / 停止（带滞回）
  → 安全：限幅 + 超时停车
  → 发布 /cmd_vel
  → Gazebo 差速插件执行
```

## 5. 模块划分（v1.0 两包）

| 包 | 职责 |
|---|---|
| robot_description | xacro 差速底盘 + RGB 摄像头 + Gazebo 插件 + world + spawn launch |
| vision_perception | 图像预处理 + 区域分析 + 决策 + 控制 + 安全（单节点） |

决策与控制暂不拆包，接口稳定后再按 PLAN.md 拆分。

## 6. 风险清单

| 风险 | 处理方式 |
|---|---|
| 地面与障碍物颜色接近 | world 用浅色地面 + 深色障碍；v1.1 增加多配色测试 |
| 单目图像无法可靠判断距离 | 不宣称测距，只做图像区域启发式；v2.0 再引入深度或激光 |
| 转向左右方向错误 | 用"已知左侧有障碍"的测试图验证图像 x 轴与机器人朝向的映射 |
| 控制来回摆动 | 方向滞回阈值 + 速度限幅 + 平滑 |
| 摄像头掉帧或节点崩溃 | 独立超时 timer，超过 timeout_sec 立即发零速度 |
| 控制指令被其他节点覆盖 | v1.0 只允许 perception 节点发布 /cmd_vel，启动文件不加额外 remap |

## 7. v1.0 验收标准

| 验收项 | 标准 |
|---|---|
| 环境启动 | 按 README 可重复启动仿真与感知节点 |
| 图像处理 | 正常图像可处理；空图像 / 错误编码不导致节点崩溃 |
| 区域检测 | 对预设测试图像输出正确格式的掩膜与状态 |
| 避障决策 | 左 / 中 / 右受阻的测试案例输出符合预期 |
| 安全行为 | 图像超时、结果无效、全部受阻时停止发出前进指令 |
| 闭环演示 | 预设障碍场景中完成路线且不碰撞 |
| 可复现性 | 他人按文档能够复现主要演示 |

## 8. 算法评估指标（v1.1 起正式统计）

| 指标 | 测量方法 |
|---|---|
| 可通行区域 IoU | 预测掩膜与人工标注对比 |
| 区域误判率 | 障碍被错判为可通行的比例 |
| 避障成功率 | 成功次数 / 总测试次数 |
| 碰撞次数 | 每次运行统计碰撞事件 |
| 处理帧率 | 每秒处理帧数 |
| 端到端延迟 | 图像时间戳到有效决策输出 |
